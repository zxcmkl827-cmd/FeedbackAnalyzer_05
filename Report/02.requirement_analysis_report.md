## 2. 종합 의견

현재 FeedbackAnalyzer는 피드백 입력, 단순 감정 분석, 키워드 분류, 필터링, CSV 다운로드 흐름을 데모 수준으로 제공한다. 그러나 C++17, CMake, Google Test 기반의 학습용 리팩토링 프로젝트로 사용하기에는 테스트 구조, 모듈 분리, 예외 처리, 경계값 처리 측면에서 보완이 필요하다.

특히 `main.cpp`에 라우팅, HTML 렌더링, CSV 파싱, 다운로드 처리가 집중되어 있어 단위 테스트 작성이 어렵다. 또한 감정/키워드 판정 기준이 여러 위치에 중복되어 분석 결과와 필터 결과가 달라질 수 있다.

## 7. 개선 우선순위

1. `main.cpp`에서 비즈니스 로직을 분리하여 테스트 가능한 core 라이브러리 타깃을 만든다.
2. CMake에 Google Test 기반 `feedback_analyzer_tests` 타깃과 `ctest` 실행 구성을 추가한다.
3. CSV 업로드/다운로드 로직을 별도 모듈로 분리하고 CSV 경계값 테스트를 우선 작성한다.
4. 감정 키워드와 필터 키워드의 중복을 제거하고 `Constants` 중심의 단일 판정 기준으로 통합한다.
5. `Session`과 `fil_data` 같은 전역 상태를 명시적 상태 객체로 대체한다.
6. 빈 입력, 잘못된 CSV, 다운로드 대상 없음, 포트 사용 중 등의 오류 정책을 명확히 한다.

## 8. 결론

FeedbackAnalyzer는 리팩토링 학습용 프로젝트로서 코드 스멜과 개선 포인트가 명확하게 드러난다. 다만 요구사항을 검증 가능한 형태로 만들기 위해서는 기능 추가보다 먼저 테스트 가능한 구조 분리와 Google Test 기반 자동화가 필요하다.

우선 개선 대상은 CSV 처리, 감정/키워드 판정 기준 통합, 전역 상태 제거, CMake 테스트 타깃 추가이다. 이 항목들이 정리되면 이후 기능 개선과 리팩토링을 안정적으로 진행할 수 있다.
