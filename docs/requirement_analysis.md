# FeedbackAnalyzer 요구사항 분석

## 1. 분석 범위

본 문서는 `README.md`와 `project_purpose.md`에 정의된 FeedbackAnalyzer 프로젝트 요구사항을 C++ QA 엔지니어 관점에서 재정리한 문서이다. 분석 기준은 C++17, CMake, Google Test 기반의 빌드 및 테스트 가능성을 포함한다.

| 구분 | 분석 대상 | QA 관점 |
|---|---|---|
| 기능 요구사항 | 피드백 입력, CSV 업로드, 감정 분석, 키워드 분류, 필터링, 다운로드 | 요구 기능이 실제 코드에서 동작 가능한지 확인 |
| 비기능 요구사항 | C++17, CMake, 테스트 가능한 구조, 유지보수성 | 빌드/테스트 자동화와 모듈 분리 수준 확인 |
| 품질 요구사항 | 예외 처리, 경계값 처리, 입력 검증, 상태 관리 | 오류 상황에서 예측 가능한 결과를 제공하는지 확인 |

## 2. C++ 관점 요구사항 재정리

| ID | 요구사항 | C++ 구현 관점의 수용 기준 | 현재 상태 |
|---|---|---|---|
| RQ-01 | 텍스트 피드백 수동 입력 | 빈 문자열과 공백 입력을 구분 처리하고, 입력된 피드백을 세션 또는 저장소에 누적한다. | 부분 구현 |
| RQ-02 | CSV 업로드 | `text` 컬럼을 검증하고, quoted field, 쉼표, 줄바꿈, 빈 행, 잘못된 인코딩을 처리한다. | 부분 구현 |
| RQ-03 | 감정 분석 | 긍정/부정/중립 판정 규칙이 일관되고 테스트 가능해야 하며, 충돌 키워드 우선순위가 명시되어야 한다. | 부분 구현 |
| RQ-04 | 키워드 기반 분류 | 카테고리별 키워드가 단일 데이터 소스에서 관리되고, 분석과 필터링이 동일한 기준을 사용해야 한다. | 부분 구현 |
| RQ-05 | 피드백 필터링 | 감정/키워드 단독 또는 조합 필터가 동일한 분석 기준으로 결과를 반환한다. | 부분 구현 |
| RQ-06 | 분석 결과 시각화 | 감정/카테고리별 분포를 사용자에게 명확하게 보여주고, 데이터가 없을 때도 명확한 메시지를 제공한다. | 단순 카운트 표시 |
| RQ-07 | 결과 CSV 다운로드 | 현재 분석 또는 필터링 결과를 RFC 4180에 가깝게 escaping하여 다운로드한다. | 부분 구현 |
| RQ-08 | CMake 빌드 | 애플리케이션 타깃과 테스트 타깃이 분리되고, `ctest`로 실행 가능해야 한다. | 앱 타깃만 존재 |
| RQ-09 | Google Test | 분석기, 필터, CSV 파서, HTML/CSV escaping, 경계값 테스트가 자동화되어야 한다. | 미구현 |
| RQ-10 | 테스트 가능한 구조 | HTTP 서버 시작 로직과 비즈니스 로직이 분리되어 단위 테스트가 가능해야 한다. | 미흡 |

## 3. 현재 코드 사용 시 부족한 기능 분석

| 영역 | 현재 구현 | 부족한 기능 또는 리스크 | 개선 필요성 |
|---|---|---|---|
| 빌드 구성 | `feedback_analyzer` 실행 파일만 생성 | Google Test 타깃, `enable_testing()`, `ctest` 연동이 없다. | 높음 |
| 모듈 구조 | `main.cpp`에 라우팅, HTML 렌더링, CSV 파싱, 다운로드가 함께 존재 | 단위 테스트가 어렵고 변경 영향 범위가 크다. | 높음 |
| CSV 업로드 | 첫 줄을 무조건 header로 건너뛰고 첫 번째 컬럼만 사용 | `text` 컬럼명 검증, 컬럼 순서 변경, quoted comma, escaped quote, 멀티라인 CSV 처리가 부족하다. | 높음 |
| CSV 다운로드 | 필터링 결과 전역 변수 `fil_data`만 다운로드 | 분석 직후 필터링하지 않은 결과는 다운로드되지 않을 수 있고, 쉼표/개행/따옴표 escaping이 없다. | 높음 |
| 감정 분석 | 키워드 포함 여부로 긍정 우선, 이후 부정 판정 | 긍정/부정 키워드가 동시에 포함된 문장의 판정 기준이 명시되어 있지 않다. | 중간 |
| 중립 처리 | 감정 분석은 미매칭을 중립으로 처리 | 중립 키워드 목록과 기본 중립 처리 기준이 분석기와 필터에서 다르게 관리된다. | 중간 |
| 키워드 필터 | 필터링 시 `main` 키워드를 제외하고 세부 키워드만 검사 | "배송"처럼 대표 키워드만 포함된 피드백이 키워드 필터에서 누락될 수 있다. | 높음 |
| 키워드 데이터 | `Constants`와 `Filters`에 감정 키워드가 중복 존재 | 분석 결과와 필터 결과가 서로 달라질 가능성이 있다. | 높음 |
| 상태 관리 | `Session`, `fil_data`, 분석기 전역 상태 사용 | 동시 요청, 사용자별 세션 분리, 테스트 격리가 어렵다. | 높음 |
| 로깅 | 콘솔 출력 중심 | 화면 표시 여부, 로그 레벨 설정, 테스트 가능한 로그 수집 기능이 부족하다. | 중간 |
| 파일 처리 | `FileHandler`는 콘솔 출력만 수행 | 실제 저장/로드 기능이 없고 현재 기능 흐름에서도 사용되지 않는다. | 낮음 |
| UI | HTML 문자열을 C++ 코드에서 직접 조립 | XSS/escaping 누락, 유지보수성, 테스트 용이성이 낮다. | 중간 |

## 4. 예외 및 경계값 처리 분석

| 입력/상황 | 기대 처리 | 현재 처리 | QA 판단 |
|---|---|---|---|
| 빈 텍스트 입력 | 사용자에게 입력 필요 메시지 표시 | 아무 피드백도 추가하지 않지만 성공 메시지는 기존 개수 기준으로 표시 | 개선 필요 |
| 공백만 있는 텍스트 | trim 후 빈 값으로 처리하고 경고 표시 | 추가하지 않음, 경고 없음 | 개선 필요 |
| 매우 긴 텍스트 | 최대 길이 제한 또는 명확한 오류 응답 | 제한 없음 | 개선 필요 |
| HTML 특수문자 포함 텍스트 | 화면 출력 시 escaping | 일부 문자(`&`, `<`, `>`, `"`)만 escaping | 부분 적합 |
| CSV 파일 미첨부 | 업로드 실패 또는 경고 메시지 | 특별한 오류 없이 성공 화면 반환 가능 | 개선 필요 |
| 빈 CSV 파일 | 데이터 없음 메시지 | 특별한 오류 없음 | 개선 필요 |
| header 없는 CSV | 형식 오류 또는 정책에 따른 처리 | 첫 줄을 무조건 버림 | 개선 필요 |
| `text` 컬럼이 없는 CSV | 명확한 형식 오류 | 첫 번째 컬럼을 텍스트로 간주 | 개선 필요 |
| quoted comma 포함 CSV | 한 필드로 유지 | 단순 quote 토글 방식으로 일부만 처리 | 개선 필요 |
| escaped quote 포함 CSV | `""`를 quote 문자로 처리 | 지원하지 않음 | 개선 필요 |
| 멀티라인 CSV 필드 | 한 레코드로 처리 | 줄 단위 파싱이라 깨짐 | 개선 필요 |
| 긍정/부정 동시 키워드 | 우선순위 또는 복합 감정 정책 필요 | 긍정이 우선된다. | 명세 필요 |
| 감정 키워드 미매칭 | 중립으로 분류 | 중립 처리 | 부분 적합 |
| 존재하지 않는 필터값 | 잘못된 요청으로 처리 | 결과 없음 또는 내부 map 변경 가능 | 개선 필요 |
| 필터 결과 없음 | 사용자에게 결과 없음 표시 | 경고 메시지 표시 | 적합 |
| 다운로드 전 필터 미수행 | 전체 결과 또는 현재 결과 다운로드 | `fil_data`가 비어 있으면 빈 CSV 가능 | 개선 필요 |
| 다중 사용자 동시 요청 | 사용자별 데이터 격리 | static 전역 상태 공유 | 개선 필요 |
| 서버 포트 사용 중 | 기동 실패 로그와 종료 코드 제공 | `listen` 결과 확인 없음 | 개선 필요 |

## 5. Google Test 기반 테스트 요구사항

1. 테스트 타깃 분리
   - `TextAnalyzer`, `Filters`, CSV 파서, CSV writer, HTML escaping 등은 실행 파일의 `main()`에 묶이지 않은 라이브러리 타깃으로 분리해야 한다.
   - CMake에는 `enable_testing()`, Google Test 연결, `add_test()` 구성이 필요하다.

2. 단위 테스트 우선순위

| 우선순위 | 테스트 대상 | 대표 테스트 케이스 |
|---|---|---|
| P1 | `TextAnalyzer` | 긍정, 부정, 중립, 키워드 미매칭, 긍정/부정 동시 포함 |
| P1 | `Filters` | 감정 필터, 키워드 필터, 조합 필터, `전체` 필터, 결과 없음 |
| P1 | CSV 파싱 | header 검증, 빈 파일, quoted comma, escaped quote, 잘못된 행 |
| P2 | CSV 다운로드 | 쉼표, 개행, 따옴표 포함 텍스트 escaping |
| P2 | 입력 처리 | 빈 문자열, 공백 문자열, 긴 문자열, URL encoding 오류 |
| P2 | 상태 관리 | 요청 간 데이터 격리, 필터 전/후 다운로드 대상 |
| P3 | UI 렌더링 | HTML escaping, 결과 없음 메시지, 오류 메시지 표시 |

3. 테스트 가능성을 위한 구조 변경 요구
   - `main.cpp` 내부 static 함수인 `parseForm`, `parseCsvLine`, `escapeHtml`을 별도 모듈로 이동한다.
   - 감정/카테고리 키워드는 `Constants` 하나의 데이터 소스에서 읽도록 통합한다.
   - `Session`과 `fil_data` 같은 전역 상태는 요청 범위 또는 명시적 상태 객체로 대체한다.
   - HTTP handler는 비즈니스 로직 클래스를 호출만 하도록 얇게 유지한다.

## 6. CMake 요구사항

| 항목 | 요구사항 |
|---|---|
| C++ 표준 | `CMAKE_CXX_STANDARD 17`, `CMAKE_CXX_STANDARD_REQUIRED ON` 유지 |
| 앱 타깃 | HTTP 서버 실행 파일 `feedback_analyzer` 유지 |
| 라이브러리 타깃 | 분석/필터/CSV/렌더링 로직을 테스트 가능한 `feedback_analyzer_core` 형태로 분리 |
| 테스트 타깃 | `feedback_analyzer_tests` 추가 |
| 테스트 실행 | `ctest --test-dir build`로 실행 가능 |
| 플랫폼 | Windows MinGW/MSVC와 GCC/Clang에서 빌드 가능하도록 플랫폼 의존 코드를 격리 |

## 7. 개선 우선순위

1. Google Test 도입을 위해 비즈니스 로직을 실행 파일에서 분리한다.
2. CSV 업로드/다운로드를 별도 파서와 writer로 분리하고 경계값 테스트를 추가한다.
3. 감정 키워드와 필터 키워드의 중복을 제거하고 분석/필터 판정 기준을 통합한다.
4. 전역 상태를 제거하거나 명시적 상태 객체로 이동해 테스트 격리와 동시 요청 안정성을 확보한다.
5. 빈 입력, 잘못된 CSV, 필터 결과 없음, 다운로드 대상 없음에 대한 사용자 메시지와 HTTP 응답 정책을 명확히 한다.
6. `README.md`의 기능 요구사항과 `project_purpose.md`의 리팩토링 학습 목표를 테스트 가능한 체크리스트로 연결한다.

## 8. QA 결론

현재 구현은 데모 수준의 피드백 입력, 단순 키워드 분석, 필터링, 다운로드 흐름을 제공하지만, C++17/CMake/Google Test 기반의 학습용 리팩토링 프로젝트로 사용하기에는 테스트 구조와 예외/경계값 처리가 부족하다. 특히 CSV 처리, 감정/키워드 판정 기준 중복, 전역 상태, 다운로드 대상 관리, 테스트 타깃 부재는 우선 개선 대상이다.

요구사항을 검증 가능한 형태로 만들기 위해서는 기능 구현보다 먼저 핵심 로직의 분리와 Google Test 기반 자동 테스트 구성이 필요하다.
